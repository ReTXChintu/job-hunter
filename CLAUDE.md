# Job Hunter – notes for Claude Code sessions in this repo

- Monorepo: pnpm workspace (`apps/desktop`, `apps/backend`, `apps/web`, `packages/*`) + Cargo workspace (`crates/job-hunter-core`, `apps/desktop/src-tauri`, `crates/job-hunter-relay`) + a standalone Flutter app (`apps/mobile`, its own pub workspace, not part of pnpm/Cargo).
- Mobile companion app (`apps/mobile`) is review-only: no AI, no job data of its own. It reaches the desktop through the self-hosted server (`apps/backend`, which speaks the relay protocol in `docs/mobile-protocol.md`; `crates/job-hunter-relay` is the older standalone equivalent). Every action it sends is dispatched by `crates/job-hunter-core/src/remote/dispatch.rs` to the *same* `orchestrator` functions the Tauri commands call -- never add a phone-only code path that bypasses approval gating. See `docs/mobile.md` and `docs/relay.md`.
- `apps/backend` is the one self-hosted server (Node/Fastify, run under PM2 via `ecosystem.config.cjs` and the root `server:*` scripts, reached as `http://<ip>:<port>`). It is wire-compatible with `job-hunter-relay`'s accounts/devices/pairing/WebSocket protocol, adds an account-scoped data API (`/v1/data/:collection`) and joined read views (`/v1/applications`), and serves the read-only web app (`apps/web`) at `/` and the newest APK at `/downloads/android`. The desktop syncs through it (`store/backend.rs`, `store/sync.rs`) and routes the mobile connection through it; both are optional. See `docs/backend.md` and `docs/deploy.md`.
- The server address is fixed at build time: `JOB_HUNTER_BACKEND_URL` for the desktop (`crates/job-hunter-core/src/backend_url.rs`) and `--dart-define=BACKEND_URL` for mobile (`apps/mobile/lib/config.dart`), both from the `BACKEND_URL` GitHub secret in `.github/workflows/build.yml`. Don't add a server URL field back to either app.
- `apps/web` is read-only by design: never add approve/reject/apply actions there; those go through the desktop's approval-gated orchestrator.
- Versions: one version for the whole repo, released with `pnpm release` (release-it, `.release-it.json`) from the root; `scripts/sync-versions.mjs` propagates it to every app (package.json files, tauri.conf.json, Cargo workspace + lock, pubspec.yaml). Never hand-edit a single app's version; `pnpm versions:check` must pass. The apps check the server's `/v1/downloads` for updates; the desktop installs signed ones via `tauri-plugin-updater` (`apps/desktop/src-tauri/src/updates.rs`), keeping `requireSignedVersion` on since the manifest is served over plain HTTP.
- Run checks with `scripts/check-all.sh` (or `.ps1`). Rust tests include a mock end-to-end pipeline in `crates/job-hunter-core/tests/mock_pipeline.rs`.
- The agent's instructions live in `agent/` and are embedded at compile time by `crates/job-hunter-core/src/prompts.rs`; edit the markdown/schema files, then rebuild.
- TS types in `packages/types` must mirror the Rust domain structs (serde camelCase). Change both together.
- Never add an Anthropic API key or direct API calls: all AI runs through the user's `claude` CLI (`claude/runner.rs`).
- Approval gating is enforced in `domain/application.rs` (`can_transition_to`) and `agent/steps.rs::apply`; do not weaken it.
- Mock mode (`MOCK_MODE=true`) uses `claude/mock.rs` and `agent/fixtures`; keep it deterministic and never let it report a real submission.
